## A. Integer-Based Ranking

1. ROW_NUMBER() - assigns an unique number to each row but it does not handle the ties (There is no gap in ranking)
2. RANK() - assigns an unique number to each row but it handles the ties (There will be a gap in ranking)
3. DENSE_RANK() - assigns an unique number to each row but it handles the ties (There is no gap in ranking)
4. NTILE(n) - divides the rows into a specified number of approximately equal groups (Buckets)
   - `Bucket Size = Number of rows / Number of buckets`
   - If there is an odd number of rows in the table, then the larger group will appear first
   - Usecases - Data segmentation | Data Equalizing Processing (OR) ETL Processing

### Scenario 1 - Rank the products based on their price

```sql
-- without partititon clause
SELECT month, product, price,
    ROW_NUMBER() OVER(ORDER BY price DESC) AS ranked_products
    RANK()       OVER(ORDER BY price DESC) AS ranked_products
    DENSE_RANK() OVER(ORDER BY price DESC) AS ranked_products
    FROM products

-- with partition clause
SELECT month, product, price,
    ROW_NUMBER() OVER(PARTITION BY product ORDER BY price DESC) AS ranked_products
    RANK()       OVER(PARTITION BY product ORDER BY price DESC) AS ranked_products
    DENSE_RANK() OVER(PARTITION BY product ORDER BY price DESC) AS ranked_products
    FROM products
```

### Scenario 2 - Top highest product in each category (best performance - Top N analysis)

```sql
SELECT
    month, product, price,
    ROW_NUMBER() OVER(PARTITION BY product ORDER BY price DESC) AS highest_products,
    FROM products WHERE highest_products = 1
```

### Scenario 3 - Find the lowest product based on their total price (worst performance - Bottom N analysis)

```sql
SELECT * FROM (
    SELECT month, product, price
    SUM(price) AS total_price,
    ROW_NUMBER() OVER(ORDER BY SUM(price)) AS product_ranks
    FROM products GROUP BY product
) t WHERE product_ranks <= 2
```

### Scenario 6 - Data Segementation (NTILE(3)) - high | medium | low

```sql
SELECT *,
    CASE buckets
        WHEN 1 THEN 'High'
        WHEN 2 THEN 'Medium'
        WHEN 3 THEN 'Low'
    END AS buckets_segmentation
    FROM (SELECT month, price, product
            NTILE(3) OVER(ORDER BY price DESC) AS buckets
            FROM products) t
```

## B. Percentage-Based Ranking

1. `CUME_DIST() = Position Number / Number of rows`

   - Cumulative Distributions calculates the distribution of data points within a window
   - If there are two or more values same after sorting, then the last position of the value will be considered as a position number

2. `PERCENT_RANK() = Position Number - 1 / Number of rows - 1`

   - If there are two or more values same after sorting, then the first position of the value will be considered as a position number

### Scenario 7 - Find the products that fall with the highest 40% of the price

```sql
SELECT *,
    CONCAT(highest_percentage * 100, '%') AS percentage
    FROM(SELECT product, price
            CUME_DIST() OVER(ORDER BY price) AS highest_percentage
            FROM products) t WHERE highest_percentage <= 0.4
```
